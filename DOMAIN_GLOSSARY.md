# FitForge AI - Domain Glossary

**Purpose:** Single source of truth for all business terminology. Every AI coding agent, developer, and stakeholder must use these terms exactly as defined here.

**Version:** 1.0
**Last Updated:** 2026-07-28

---

## 1. How to Use This Glossary

- When writing code, use the **Code Name** column for class/variable naming
- When designing APIs, use the **API Path** column for endpoint naming
- When writing documentation, use the **Term** column for prose
- Never use synonyms or abbreviations not listed here
- If a term is missing, add it here first before using it elsewhere

---

## 2. Core Entities

### 2.1 User

**Definition:** A registered account holder. The User is the top-level identity that owns all personal data. Every WorkoutPlan, ProgressLog, and Subscription belongs to exactly one User.

**Code Name:** `User`

**API Path:** `/users`

**Key Attributes:**

| Attribute | Type | Required | Description |
|-----------|------|----------|-------------|
| id | UUID | Yes | Primary key. Generated on registration. |
| email | String(255) | Yes | Unique. Used for login. |
| passwordHash | String(255) | Yes | bcrypt hash. Never exposed via API. |
| role | Enum | Yes | `user`, `admin`, `premium`. Default: `user`. |
| profile | JSONB | Yes | See UserProfile value object. |
| createdAt | TIMESTAMPTZ | Yes | Set on creation. Never changes. |
| updatedAt | TIMESTAMPTZ | Yes | Set on every update. |

**Relationships:**
- User **owns** many WorkoutPlans
- User **has one** Subscription
- User **has many** ProgressLogs
- User **has one** UserProfile (embedded in profile JSONB)

---

### 2.2 UserProfile

**Definition:** A value object stored as JSONB inside the User's `profile` column. Contains physical attributes, fitness preferences, and goals. Required for AI workout generation.

**Code Name:** `UserProfile` (value object, not a separate table)

**Key Attributes:**

| Attribute | Type | Required | Validation |
|-----------|------|----------|------------|
| firstName | String | Yes | 1-50 chars, letters and spaces only |
| lastName | String | Yes | 1-50 chars, letters and spaces only |
| dateOfBirth | ISO 8601 Date | Yes | Must be 13+ years old |
| gender | Enum | No | `male`, `female`, `other`, `prefer_not_to_say` |
| heightCm | Number | No | 50-300 |
| weightKg | Number | No | 20-500 |
| fitnessLevel | Enum | Yes* | `beginner`, `intermediate`, `advanced` |
| goals | Array[Enum] | Yes* | `strength`, `hypertrophy`, `endurance`, `weight_loss`, `flexibility` |
| equipmentAvailable | Array[Enum] | No | `barbell`, `dumbbells`, `machines`, `bodyweight`, `bands` |
| limitations | String | No | Max 500 chars. Injuries or restrictions. |
| avatarUrl | String | No | URL to profile image |

*Required for AI workout generation. Manual plan creation works without these.

---

### 2.3 WorkoutPlan

**Definition:** A structured fitness program spanning multiple weeks. Contains an ordered collection of WorkoutSessions. Can be created manually by the user or generated by the AI service. This is the primary unit of workout organization.

**Code Name:** `WorkoutPlan`

**API Path:** `/workout-plans`

**Key Attributes:**

| Attribute | Type | Required | Description |
|-----------|------|----------|-------------|
| id | UUID | Yes | Primary key |
| userId | UUID | Yes | FK to User. Owner of the plan. |
| planType | Enum | Yes | `strength`, `hypertrophy`, `cardio`, `flexibility` |
| title | String(255) | Yes | User-provided or AI-generated title |
| description | Text | No | Max 2000 chars |
| daysPerWeek | Integer | Yes | 1-7. How many days per week the plan requires. |
| totalWeeks | Integer | Yes | 1-52. Duration of the program. |
| status | Enum | Yes | `draft`, `active`, `completed`, `paused`. Default: `draft`. |
| generatedBy | Enum | Yes | `ai`, `manual`. How the plan was created. |
| aiMetadata | JSONB | No | See AIGenerationMetadata value object. Only present when generatedBy = `ai`. |
| createdAt | TIMESTAMPTZ | Yes | Set on creation |
| updatedAt | TIMESTAMPTZ | Yes | Set on every update |
| isDeleted | Boolean | Yes | Soft delete flag. Default: `false`. |
| deletedAt | TIMESTAMPTZ | No | Set when soft-deleted |

**Lifecycle States:**

```
draft --> active --> completed
  |        |
paused   paused
  |        |
active   completed
```

- `draft`: Plan created but not yet started. Can be edited freely.
- `active`: Plan is in use. Sessions are being logged.
- `paused`: Plan temporarily suspended. Can resume to `active`.
- `completed`: All sessions finished. Read-only.

**Relationships:**
- WorkoutPlan **belongs to** one User
- WorkoutPlan **has many** WorkoutSessions (ordered by orderIndex)

---

### 2.4 WorkoutSession

**Definition:** A single training day within a WorkoutPlan. Contains an ordered collection of ExerciseSets. Also referred to as a "Session" in the API. The database table is named `workouts` for historical reasons, but in all code, documentation, and API paths, this entity is called **WorkoutSession**.

**Code Name:** `WorkoutSession`

**API Path:** `/workout-plans/{planId}/sessions`

**Key Attributes:**

| Attribute | Type | Required | Description |
|-----------|------|----------|-------------|
| id | UUID | Yes | Primary key |
| planId | UUID | Yes | FK to WorkoutPlan |
| dayOfWeek | Integer | Yes | 1-7 (1 = Monday, 7 = Sunday) |
| date | TIMESTAMPTZ | Yes | Scheduled date for this session |
| title | String(255) | Yes | e.g., "Day 1: Upper Body" |
| description | Text | No | Session description |
| orderIndex | Integer | Yes | Position within the plan (0-indexed) |
| durationMinutes | Integer | No | Actual or estimated duration |
| caloriesBurned | Integer | No | Estimated calories |
| completed | Boolean | Yes | Default: `false`. Set to true when all sets are logged. |
| completedAt | TIMESTAMPTZ | No | Timestamp when session was marked complete |
| createdAt | TIMESTAMPTZ | Yes | Set on creation |

**Lifecycle States:**

```
scheduled --> in_progress --> completed
```

- `scheduled`: Session planned for a future date. No sets logged yet.
- `in_progress`: User has started logging sets.
- `completed`: All sets logged and marked complete.

**Relationships:**
- WorkoutSession **belongs to** one WorkoutPlan
- WorkoutSession **has many** ExerciseSets (ordered by setNumber)

---

### 2.5 Exercise

**Definition:** A catalog entry representing a physical movement (e.g., "Barbell Bench Press"). Admin-managed. Not user-specific. Users select exercises from this catalog when building workouts. The AI service also references exercises by name when generating plans.

**Code Name:** `Exercise`

**API Path:** `/exercises`

**Key Attributes:**

| Attribute | Type | Required | Description |
|-----------|------|----------|-------------|
| id | UUID | Yes | Primary key |
| name | String(100) | Yes | Unique display name |
| category | Enum | Yes | `chest`, `back`, `legs`, `shoulders`, `arms`, `core`, `cardio` |
| difficulty | Enum | Yes | `beginner`, `intermediate`, `advanced` |
| equipment | String(100) | No | Primary equipment needed |
| instructions | Text | No | Step-by-step execution guide |
| muscleGroup | JSONB | No | Array of targeted muscle groups |
| createdAt | TIMESTAMPTZ | Yes | Set on creation |
| updatedAt | TIMESTAMPTZ | Yes | Set on every update |

**Relationships:**
- Exercise **has many** ExerciseSets (referenced by exercise_id)
- Exercise **has many** ExerciseVariations (self-referential many-to-many)

---

### 2.6 ExerciseSet

**Definition:** A single set within a WorkoutSession. Records the exercise performed, number of reps, weight used, and completion status. This is the atomic unit of workout logging.

**Code Name:** `ExerciseSet`

**API Path:** `/sessions/{sessionId}/sets`

**Key Attributes:**

| Attribute | Type | Required | Description |
|-----------|------|----------|-------------|
| id | UUID | Yes | Primary key |
| workoutId | UUID | Yes | FK to WorkoutSession |
| exerciseId | UUID | Yes | FK to Exercise |
| setNumber | Integer | Yes | 1-indexed position within the session |
| reps | Integer | No | Number of reps. Null for timed exercises. |
| weightKg | Decimal(10,2) | No | Weight in kilograms. Null for bodyweight. |
| completed | Boolean | Yes | Default: `false` |
| notes | Text | No | User notes for this set |
| createdAt | TIMESTAMPTZ | Yes | Set on creation |

**Validation Rules:**
- setNumber must be >= 1
- reps must be 0-99 (or null)
- weightKg must be 0-999 (or null)
- An ExerciseSet cannot be edited after 24 hours (business rule)

**Relationships:**
- ExerciseSet **belongs to** one WorkoutSession
- ExerciseSet **references** one Exercise

---

### 2.7 ExerciseVariation

**Definition:** A many-to-many self-referential relationship between Exercises. Represents alternative movements (e.g., "Barbell Bench Press" can vary to "Dumbbell Bench Press" or "Incline Bench Press").

**Code Name:** `ExerciseVariation`

**Key Attributes:**

| Attribute | Type | Required | Description |
|-----------|------|----------|-------------|
| exerciseId | UUID | Yes | FK to Exercise (the base exercise) |
| variationId | UUID | Yes | FK to Exercise (the variation) |

**Relationships:**
- ExerciseVariation **links** two Exercises

---

### 2.8 ProgressLog

**Definition:** A user-recorded measurement entry. Used for tracking body metrics, personal records, and workout performance over time. Append-only (no updates, no deletes).

**Code Name:** `ProgressLog`

**API Path:** `/progress`

**Key Attributes:**

| Attribute | Type | Required | Description |
|-----------|------|----------|-------------|
| id | UUID | Yes | Primary key |
| userId | UUID | Yes | FK to User |
| workoutId | UUID | No | FK to WorkoutSession (optional context) |
| exerciseId | UUID | No | FK to Exercise (optional, for exercise-specific progress) |
| measurementDate | TIMESTAMPTZ | Yes | When the measurement was taken |
| weightKg | Decimal(10,2) | No | Body weight or exercise weight |
| reps | Integer | No | Reps performed |
| sets | Integer | No | Number of sets |
| notes | Text | No | User notes |
| createdAt | TIMESTAMPTZ | Yes | Set on creation |

**Relationships:**
- ProgressLog **belongs to** one User
- ProgressLog **optionally references** one WorkoutSession
- ProgressLog **optionally references** one Exercise

---

### 2.9 Subscription

**Definition:** A user's access tier and billing status. Controls feature availability (free vs premium vs pro). NOT tied to any specific WorkoutPlan. Each User has exactly one Subscription record.

**Code Name:** `Subscription`

**API Path:** `/subscriptions`

**Key Attributes:**

| Attribute | Type | Required | Description |
|-----------|------|----------|-------------|
| id | UUID | Yes | Primary key |
| userId | UUID | Yes | FK to User. One subscription per user (unique). |
| tier | Enum | Yes | `free`, `premium`, `pro` |
| status | Enum | Yes | `active`, `cancelled`, `expired`, `trial` |
| startedAt | TIMESTAMPTZ | Yes | When subscription began |
| expiresAt | TIMESTAMPTZ | No | When subscription ends. Null for free tier. |
| paymentProvider | String | No | `stripe`, `manual`, null (for free) |
| externalSubscriptionId | String | No | Provider's subscription ID |
| createdAt | TIMESTAMPTZ | Yes | Set on creation |
| updatedAt | TIMESTAMPTZ | Yes | Set on every update |

**Lifecycle States:**

```
trial --> active --> expired
            |
        cancelled --> expired
```

- `trial`: Free trial period (14 days).
- `active`: Paid subscription in good standing.
- `cancelled`: User cancelled. Remains active until expiresAt.
- `expired`: Subscription ended. Features downgraded to free.

**Tier Limits:**

| Tier | AI Generations/Hour | Analytics | Support |
|------|---------------------|-----------|---------|
| free | 2 | Basic | Community |
| premium | 10 | Advanced | Email |
| pro | Unlimited | Full | Priority |

**Relationships:**
- Subscription **belongs to** one User

---

### 2.10 Category

**Definition:** A classification for Exercises. Used for filtering and organizing the exercise catalog. Not a separate database table; stored as an enum on the Exercise entity.

**Code Name:** `Category` (enum, not entity)

**Valid Values:**

| Value | Display Name | Description |
|-------|--------------|-------------|
| chest | Chest | Pectoral exercises |
| back | Back | Latissimus, rhomboid, trap exercises |
| legs | Legs | Quadriceps, hamstrings, glute exercises |
| shoulders | Shoulders | Deltoid exercises |
| arms | Arms | Bicep, tricep, forearm exercises |
| core | Core | Abdominal, oblique exercises |
| cardio | Cardio | Heart rate elevation exercises |

## 3. Relationship Map

```
User (1) ----< (N) WorkoutPlan
  |                    |
  |                    +----< (N) WorkoutSession
  |                              |
  |                              +----< (N) ExerciseSet
  |                                        |
  |                                        +----> (1) Exercise
  |
  +----< (N) Subscription
  |
  +----< (N) ProgressLog ----> (0..1) WorkoutSession
                              ----> (0..1) Exercise

Exercise (M) ----< (M) Exercise (via ExerciseVariation)
```

## 4. Aggregate Roots

Aggregate roots define transaction boundaries. Operations within an aggregate root can be committed together. Operations across aggregate roots must use domain events.

| Aggregate Root | Owned Entities | Can Modify Together |
|----------------|----------------|---------------------|
| User | UserProfile (embedded), Subscription | User registration, profile update, subscription change |
| WorkoutPlan | WorkoutSession, ExerciseSet | Plan creation, session update, set logging |
| Exercise | ExerciseVariation | Admin catalog management |
| ProgressLog | (none - leaf entity) | Single progress entry |

**Rules:**
- An ExerciseSet can only be modified within its parent WorkoutSession transaction
- WorkoutPlan deletion cascades to sessions and sets
- Exercise deletion is blocked if referenced by any ExerciseSet
- ProgressLog is append-only (no updates, no deletes allowed)

## 5. Naming Rules

### In Code (C# / TypeScript)

| Context | Convention | Example |
|---------|-----------|---------|
| C# class names | PascalCase | `WorkoutSession`, `ExerciseSet` |
| C# variable names | camelCase | `workoutSession`, `exerciseSet` |
| TypeScript types | PascalCase | `WorkoutSession`, `ExerciseSet` |
| TypeScript variables | camelCase | `workoutSession`, `exerciseSet` |

### In API Paths

| Context | Convention | Example |
|---------|-----------|---------|
| Path segments | kebab-case | `/workout-plans`, `/exercise-sets` |
| Query parameters | camelCase | `?pageSize=20&sortBy=createdAt` |

### Forbidden Terms

Do NOT use these ambiguous terms. Use the approved term instead.

| Forbidden Term | Use Instead |
|----------------|-------------|
| Workout (ambiguous) | WorkoutSession or WorkoutPlan |
| Set (too vague) | ExerciseSet |
| Plan (too vague) | WorkoutPlan |
| Session (too vague) | WorkoutSession |
| Exercise Data | ExerciseSet |
| Log (too vague) | ProgressLog |
| Sub (too vague) | Subscription |
| AI Plan | WorkoutPlan (with generatedBy = 'ai') |

## 6. Value Objects

### 6.1 AIGenerationMetadata

Stored in WorkoutPlan.aiMetadata when the plan was generated by AI.

| Field | Type | Description |
|-------|------|-------------|
| modelVersion | String | AI model used (e.g., "glm-4.7-flash") |
| promptVersion | String | Prompt template version (e.g., "v1.2") |
| generationId | UUID | Idempotency key for this generation |
| inputPreferences | Object | User preferences passed to AI |
| tokenUsage | Object | `{ promptTokens, completionTokens, totalTokens }` |
| latencyMs | Number | API response time in milliseconds |
| generatedAt | ISO 8601 | When generation completed |

### 6.2 AIInputPreferences

Stored inside AIGenerationMetadata.inputPreferences.

| Field | Type | Description |
|-------|------|-------------|
| userLevel | Enum | `beginner`, `intermediate`, `advanced` |
| goal | Enum | `strength`, `hypertrophy`, `endurance`, `weight_loss`, `flexibility` |
| equipment | Array[String] | Equipment available to user |
| daysPerWeek | Integer | Requested training frequency |
| totalWeeks | Integer | Requested program duration |
| focusAreas | Array[String] | Muscle groups to prioritize |
| limitations | String | User-reported injuries or restrictions |
